# Maintenance dependencies and checks

This checklist identifies framegen-vulkan's dependencies, external interfaces, version owners, and ongoing maintenance responsibilities. Use it to review upstream changes, determine whether framegen-vulkan needs an update, fix affected code or pins, and run the relevant checks.

Keep this file focused on what to check, when to check it, and who owns the change. Exact versions belong in the linked version files; implementation details belong in component guides; review findings and test results belong in the owning compatibility records or QA evidence. Update this checklist when a dependency or maintenance responsibility changes.

[TESTING.md](TESTING.md) owns validation selection, [CLEANUPS.md](CLEANUPS.md) owns temporary compatibility removal, and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) owns license and source attribution.

## When to check

- **When upstream releases change:** review the affected dependency rows, identify changes to the interfaces framegen-vulkan uses, and fix code or pins when needed. For SteamOS, review stable releases and relevant Beta/Preview notes even before a test machine upgrades.
- **Before a framegen-vulkan release:** check for relevant upstream changes and run the applicable checks from [TESTING.md](TESTING.md) and [candidate qualification](HOW_TO_RELEASE.md#qualify-the-candidate).
- **When framegen-vulkan changes a dependency or compatibility assumption:** update its canonical owner, code, tests, and component guide together. Update this checklist if the responsibility or review trigger changes.
- **When support policy changes:** align runtime catalogues, architecture/ABI minimums, compatibility cleanup gates, installation guidance, and package checks. A newer dependency version alone does not justify removing older protocol support.
